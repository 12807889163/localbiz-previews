Step 3 — Add Four A Records (for yourdomain.com)

💡 What's an "A record"? In plain English:

An A record is one entry in the internet's phone book that says: "When someone types yourbusiness.com, send them to this server." We're adding four of them because GitHub Pages uses four servers for reliability — if one is down, the others handle your traffic.

1

Open Advanced DNS

On the domain management page (where you clicked Manage), click the Advanced DNS tab at the top.

2

Delete any pre-existing A records (only A records — leave everything else)

Namecheap sometimes adds default A records for new domains (they point to parking pages). Find them in the HOST RECORDS list — the Type column will say "A Record". Click the red trash 🗑️ icon next to each one.

⚠️ Only delete A records. Don't touch CNAME, MX, NS, or TXT records.

If you see CNAME, MX (mail), NS (nameservers), or TXT records, leave them alone — they belong to Namecheap's email/DNS setup.

3

Add four new A records (one at a time)

Click Add New Record four times, creating one record per click with these values:

TypeHostValueTTL
A Record@185.199.108.153Automatic
A Record@185.199.109.153Automatic
A Record@185.199.110.153Automatic
A Record@185.199.111.153Automatic

For each row: Type = "A Record", Host = the symbol @ (one character, not a value), Value = one of the four IP addresses above, TTL = "Automatic". Click the green ✔ save icon at the right of each row before adding the next.

ap.namecheap.com/.../advancedns

Example UI — All four A records added. Each IP address points to one of GitHub's servers.
✅ Why four IPs?

GitHub Pages runs on four servers (108, 109, 110, 111). Adding all four means your site stays online even if one of them has a hiccup. They share the same content, so visitors see no difference.

Step 4 — Add a CNAME Record (for www.yourdomain.com)

1

Click "Add New Record" one more time

Still in the HOST RECORDS section, click Add New Record one final time.

2

Fill in the CNAME record

This step handles visitors who type www.yourbusiness.com (with the www. prefix):

TypeHostValueTTL
CNAME Recordwww12807889163.github.io.Automatic

Type = "CNAME Record", Host = www, Value = 12807889163.github.io. (note the trailing dot — it must be there), TTL = Automatic.

⚠️ Spelled exactly right

The Value field must be exactly 12807889163.github.io. with a period at the end. If it's missing the period, the CNAME won't resolve. If any digit is wrong, the site won't load.

✅ DNS records are set!

All five records (4 A + 1 CNAME) are saved. DNS changes typically take 10 to 30 minutes to fully propagate, but it can be as fast as 5 minutes or as slow as 48 hours. Don't worry — your site will appear eventually.

Step 7 — Enable HTTPS (the Padlock)

💡 What's HTTPS? In plain English:

HTTPS is what puts the little padlock 🔒 in your browser's address bar. Without it, browsers show a "Not Secure" warning next to your URL — which makes visitors nervous. Turning it on gets you a free SSL certificate from Let's Encrypt (a free certificate authority) and makes your site look professional.

1

Tick the "Enforce HTTPS" checkbox

On the same GitHub Pages settings page, scroll down and tick the box that says "Enforce HTTPS".

GitHub will automatically request a free SSL certificate for your domain. This can take anywhere from 5 minutes to 24 hours, but it's almost always under 30 minutes.

✅ You're all done!

Once HTTPS is active, your website is live at https://yourbusiness.com. The padlock will show in visitors' browsers, and the site will work on every device. Tell your customers, share it on Google Business Profile, and you're in business.

Troubleshooting — "It Doesn't Work Yet"

Most issues are DNS propagation (just wait 30 more minutes). Here's a checklist of other things to verify:

🔴 "GitHub says DNS check failed"

Wait 10–30 minutes and check again. If it still fails after an hour, open your Namecheap Advanced DNS page and compare your A records to 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153 exactly — no typos.

🔴 "I see a GitHub 404 page"

Usually means you saved the custom domain in GitHub before the DNS fully propagated. Go to Settings → Pages, delete the custom domain, click Save, wait 5 minutes, then re-enter it and save again.

🔴 "Site loads but shows 'Not Secure'"

Check the Enforce HTTPS box in GitHub Pages settings. If it's already on, give it up to 24 hours — the SSL certificate can take time to provision on first setup.

🔴 "www.yourbusiness.com works but yourbusiness.com doesn't"

The four A records aren't all there. Open Namecheap → Advanced DNS and confirm you have four rows with Type "A Record", Host "@", and Values ending in .108.153, .109.153, .110.153, and .111.153.

🔴 "I never got the GitHub invite email"

Check your spam folder. If it's not there after 30 minutes, reply to your delivery email again — sometimes the invite bounces silently.

🔴 "I've waited 48 hours and nothing works"

Run this in your terminal (Mac/Linux/WSL) to check what DNS thinks your domain points to:

dig yourbusiness.com +short A

You should see four IP addresses: 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153. If you see anything else (like Namecheap parking IPs or missing values), the DNS records are wrong. Reply to your delivery email with the dig output and we'll fix it for you — no extra charge.

🔴 "I bought the domain somewhere else (GoDaddy, Cloudflare, Google Domains)"

The four A records + one CNAME work everywhere. Just open your registrar's DNS settings page instead of Namecheap's. The exact button names vary, but the values are the same.
